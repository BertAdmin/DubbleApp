# Dubble — Project Plan

## What Dubble Is

A self-custodial Bitcoin savings game that visualizes savings accounts as bubbles. Users "blow" bubbles by paying Lightning invoices and "double" them by paying the same amount again. Each bubble shows both USD and sat balances. Built on the Breez SDK (Spark) for self-custodial Lightning — users hold their own keys from day one.

---

## What Breez Is and How We're Using It

### What is Breez?

Breez is an open-source, self-custodial Lightning SDK. It lets developers add Bitcoin Lightning payments to apps without running a node, managing channels, or handling liquidity. 75+ apps have integrated it, including Cake Wallet, Wallet of Satoshi, and Yopaki.

### What is the Breez SDK — Spark?

The Spark variant is built on Spark, a Bitcoin-native Layer 2 protocol. It provides:
- **Self-custodial wallets** — users hold their own keys, Breez never touches funds
- **Lightning send/receive** — generate invoices, pay invoices, check balances
- **On-chain deposits** — users can deposit BTC to a Spark address
- **Stablecoin support** — USDB and USDT native on Spark (roadmap for us)
- **Nodeless** — no channels, no nodes, no liquidity management to worry about

### How Dubble Uses Breez

```
Dubble Flask Backend
        │
        ▼
breez-sdk-spark (Python)
        │
        ├── Create wallet (seed phrase per user)
        ├── Generate Lightning invoice (for blowing/doubling bubbles)
        ├── Check wallet balance (sync displayed balance)
        ├── Pay Lightning invoice (for withdrawals)
        └── Generate on-chain address (for deposits)
        │
        ▼
Spark L2 / Lightning Network
```

The SDK is a Python package (`breez-sdk-spark`) that we install with pip. Our Flask backend calls it directly. The user's seed phrase is generated by the SDK and stored encrypted — Breez never has access.

### Getting a Breez API Key

1. Go to https://breez.technology/request-api-key/
2. Fill out the form (name, company/project, email, message)
3. API key is sent to your email — free, no credit card
4. Add it to `.env` as `BREEZ_API_KEY=your_key_here`

## Architecture

### The Model: Ally Buckets for Bitcoin

One Spark wallet per user. Bubbles are metadata — named partitions of the wallet balance. All sats live in one place; the app's database tracks which bubble "owns" what portion.

```
┌─────────────────────────────────────────────┐
│              User's Spark Wallet             │
│         (self-custodial, one keypair)        │
│                                              │
│   ┌──────────┐ ┌──────────┐ ┌──────────┐   │
│   │ Bubble A │ │ Bubble B │ │ Bubble C │   │
│   │ 1000 sats│ │ 2000 sats│ │  500 sats│   │
│   │ $1.00    │ │ $2.00    │ │ $0.50    │   │
│   └──────────┘ └──────────┘ └──────────┘   │
│                                              │
│   Total wallet balance: 3,500 sats ($3.50)   │
└─────────────────────────────────────────────┘
```

### Bubble Lifecycle

1. **Blow:** User creates bubble → app generates Lightning invoice for 1,000 sats ($0.01 at ~$100k BTC) → user pays from external wallet → bubble appears
2. **Double:** User clicks bubble → app generates invoice for same sat amount → user pays → bubble balance doubles
3. **Edit:** User can name/label any bubble after creation
4. **Withdraw:** User selects bubble → pastes external Lightning invoice → app pays from wallet → bubble shrinks or pops (if fully withdrawn)

### User Flows

```
Blow Bubble:
  Click "Blow" → Generate invoice → Show QR → User pays → Bubble appears

Double Bubble:
  Click bubble → Confirm → Generate invoice → Show QR → User pays → Bubble grows

Withdraw:
  Click bubble → Enter amount or "all" → Paste external invoice → Confirm → Pay → Bubble shrinks/pops

Rename:
  Click bubble → Edit → Type name → Save
```

## Database Schema

```sql
CREATE TABLE users (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    username TEXT UNIQUE NOT NULL,
    password_hash TEXT NOT NULL,
    spark_wallet_id TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE wallets (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER UNIQUE NOT NULL,
    balance_sats INTEGER DEFAULT 0,
    balance_usd REAL DEFAULT 0.0,
    last_synced_at TIMESTAMP,
    FOREIGN KEY(user_id) REFERENCES users(id)
);

CREATE TABLE bubbles (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER NOT NULL,
    name TEXT DEFAULT '',
    balance_sats INTEGER DEFAULT 0,
    balance_usd REAL DEFAULT 0.0,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY(user_id) REFERENCES users(id)
);

CREATE TABLE invoices (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    bubble_id INTEGER NOT NULL,
    payment_hash TEXT UNIQUE NOT NULL,
    payment_request TEXT NOT NULL,
    amount_sats INTEGER NOT NULL,
    amount_usd REAL,
    status TEXT DEFAULT 'pending',
    invoice_type TEXT DEFAULT 'blow',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    paid_at TIMESTAMP,
    FOREIGN KEY(bubble_id) REFERENCES bubbles(id)
);
```

### invoice_type values
- `blow` — creating a new bubble
- `double` — doubling an existing bubble
- `withdraw` — sending sats out (stored for audit, sats leave wallet)

## Security Requirements

These are non-negotiable before any feature work:

1. **bcrypt password hashing** — replace plaintext storage/comparison
2. **Remove `DROP TABLE` on startup** — currently destroys all data every restart
3. **Real secret key** — generate with `python -c "import secrets; print(secrets.token_hex(32))"`
4. **CSRF protection** — Flask-WTF on all forms
5. **Debug off in production** — `debug=False`
6. **Per-request DB connections** — or move to PostgreSQL with connection pooling
7. **Seed phrase encryption** — encrypt before storage, never log
8. **Input validation** — validate all API inputs server-side

## Development Phases

### Phase 0: Security + Project Cleanup
- Fix all security issues from code critique
- Restructure into `app/` package layout
- Set up `.env`, `requirements.txt`, proper Flask config
- Set up Breez SDK connection and wallet creation

### Phase 1: Core Bubble Mechanics
- Blow a bubble (generate invoice, show QR, detect payment, create bubble)
- Double a bubble (generate invoice for same amount, show QR, update bubble)
- Display bubbles with correct sizing (log or sqrt scale)
- BTC/USD price display via CoinGecko

### Phase 2: User Management + Editing
- Auth system (register, login, logout) with bcrypt
- Bubble naming/editing
- Withdraw (pay external invoice from bubble balance)
- Pop bubble (delete when balance reaches zero)

### Phase 3: Polish + UX
- Bubble animation (growth/shrink on double/withdraw)
- QR code display for invoices
- Copy invoice to clipboard
- Payment status polling (pending → confirmed)
- Responsive layout

### Phase 4: RoadMAP (future)
- Stablecoin support (USDB/USDT via Breez SDK)
- Fiat on-ramp (integrate MoonPay or Cash App via Breez)
- In-app payment (fund from internal balance)
- Cardano/Midnight integration
- Mobile app (React Native + Breez SDK)
- Bubble physics (Canvas rendering, floating, collisions)
